# 五分钟实验讲解提纲

## 1. 问题与测量（约一分钟）

同一文档页面对应多个不同真实问题。每个问题仍需独立语言推理，但视觉图像没有变化。Qwen3-VL-2B 在本机约 36.7% 的 GPU worker service time 用于视觉编码，单独消除该阶段的 Amdahl 上限约 1.58 倍。

数据为 DocVQA 自划分：64 页/282 问开发，128 页/558 问评估，源文档互斥，问题未改写。时间由脚本合成，所有方法同一 trace。

## 2. 三层优化（约两分钟）

- O1，模型计算图：保存主 embedding 与三层 DeepStack，完整 BF16 payload 为 `V×2048×2×4` 字节。不同问题重新执行位置编码、prefill 和生成；语言 KV 仅属于当前请求。
- O2，服务运行时：只看已经就绪的前 16 个请求，保护老请求，再按图像亲和与视觉/文本成本选最多两条。调度器没有未来请求信息。
- O3，GPU/CPU 存储：相同 512/256 MiB 上限下，以历史复访和实测重编码成本/字节管理条目，GPU/CPU 完整搬运；lease 防止计算期间释放。

初版 packed BF16 视觉执行使缓存出生时的批次影响舍入，一个消融未通过质量门槛。最终对所有变体统一逐页视觉执行，保留语言 batch=2；四组真实 GPU 特征和首步 logits 对照误差均为零。初版代码和失败 gate 保留，门槛没有放宽。

## 3. 对照与实测结果（约一分钟）

五变体、三档负载、三个种子，共 45 轮，每轮 60 秒到达窗口，独立模型进程；另有 18 个辅助单元。TTFT/回答 SLO 为 0.62/1.66 秒，来自开发无排队 p95 的两倍。

0.8 档中负载 FULL goodput 为 0.933 请求/s，B0 为 0.456，比例 2.05。所有拒绝和超时留在到达分母；p95 仅描述完成请求，需和达标率并读。高负载若只有少量成功请求，须先比较绝对数，避免只看比例。

按本机中负载平均 goodput，优先配置为 O1+O2 与 LRU（V1+S）；FULL 是组合对照，叠加三项机制不代表总是更好。O3 相对 LRU 的中负载平均 goodput 差为 -0.022 请求/s，配对区间包含零，未观察到稳定的正收益。调度的 goodput 与尾延迟取舍须同时说明。

全量 FULL ANLS 为 0.88936，相对 B0 为 +0.00059；实际视觉编码从 558 次减少到 279 次。O1/O2/O3 的独立 goodput 差和三种子配对区间在 `tables/paired-effects.csv`，不只展示最终组合。

## 4. 验证与复现（约一分钟）

逐条保存原图、问题、参考答案、生成 token、计划/实际到达、首 token、EOS、缓存与显存。独立脚本重算 ANLS、SLO、唯一请求账本、配对 trace 和每批容量；Z3 对有界 lease 模型得到安全 UNSAT，移除保护后 SAT，保留反例。这项证明只覆盖有限抽象，不覆盖神经网络数值正确性。

8GB 是显卡物理容量，512 MiB 等是控制的缓存资源上限，不能混为一谈。主运行中缓存预算保护触发 0 批，存储收益按实际保留策略解释。相关工作采用不同硬件与模型，本机量化对照是统一执行配置的 Transformers 基线。

已完成结果可用 `./stage_2/run.sh verify-results` 和 `report` 重新核验、出图；全流程 `all`；保持原结果并新跑用 `rerun --output 一个新目录`。AI 辅助范围单独记录，性能数据全部来自实际 GPU 执行。
