# 第一轮经验与第二轮跨层优化方案

状态：第二轮开发验证已完成，两项新方向已实现并通过开发门槛；新独立评估和开放环矩阵尚未执行。原 45 轮主实验、18 轮辅助实验、报告与提交包完整保留。

## 1. 第一轮真正成立的经验

1. **直接减少推理计算比微调队列策略更确定。** 视觉编码占基线服务时间约 36.7%，视觉缓存的低、中负载增益配对区间为正；558 条单缓存输出 token 与基线完全一致。
2. **有效吞吐和原始推理速度必须分别报告。** 推荐组合的中负载 SLO goodput 为基线约 2.17 倍，单次离线生成吞吐约提高 17%。排队和阈值会放大 goodput 的变化，不能把它当作模型本体加速倍数。
3. **服务调度存在目标取舍。** 中负载加入图像亲和调度后，goodput 从 0.867 增至 0.989 请求/s，但首 token p95 从 2.382 增至 2.742 s；三种子的独立调度增益区间跨零。它适合作为服务对照，不再承担第二轮的核心贡献。
4. **没有触发的硬件约束不能用来证明优化价值。** 主矩阵没有因 KV/workspace 保护而缩小缓存上限。价值替换在三个预算上的吞吐差绝对值最大约 0.59%，未形成稳定收益。第二轮直接检查 GPU 执行与访存状态，不把又一种替换规则计为新的硬件层优化。
5. **同一计算的执行形状也属于正确性条件。** 初版 packed BF16 视觉编码引起舍入变化，导致一个消融未通过原质量门槛。统一逐页视觉执行后，完整特征、首步 logits 和 CPU/GPU 往返检查通过。后续前缀切分和静态 KV 也必须与原生执行比较，而不能只比较新代码的两个开关。
6. **先做小规模门槛验证，再跑大矩阵。** 第二轮先只读开发集，分开检查语义、质量、内存、实际阶段时间与底层调用，再决定正式矩阵。失败尝试和原始数据同样归档。

## 2. 保留应用，替换两个方向

应用仍是同一文档页面的多个独立真实问题，模型和图片预算不变。保留第一轮视觉特征缓存作为基础和强基线，替换证据较弱的调度与价值替换。

| 项目 | 层次 | 改变的对象 | 必须出现的独立证据 |
| --- | --- | --- | --- |
| 保留：完整视觉特征缓存 | 模型计算图层 | 重复 ViT 与 DeepStack 输出 | 视觉编码数减少，特征与答案校验 |
| 新方向 A：多模态公共前缀 KV 复用 | 软件算法／模型执行图层 | 图像及固定头部的语言 prefill | 命中时实际 prefill token 数、TTFT、复制成本、前缀隔离与答案质量 |
| 新方向 B：静态 KV 与 CUDA Graph 解码 | CPU–GPU 协同／GPU 底层执行层 | 逐 token 的 CUDA 命令提交、静态显存寻址与执行空隙 | 每步实际 cudaLaunchKernel/cudaGraphLaunch 次数、decode 时间、显存与图构建成本 |

**计数原则：视觉缓存和前缀缓存都属于计算复用层，不把它们冒充两个不同层次。课程要求的两层由“模型计算复用”与“GPU 执行”共同满足。** GPU 方向通过 CUDA 图、设备端游标和固定地址缓冲实现，不能只凭使用了 GPU 就称为硬件层优化。

建议第二轮题目：**面向文档视觉问答的跨层推理优化——多模态前缀状态复用与 CUDA Graph 解码。**

## 3. 新方向 A：只复用公共前缀，问题相关状态独立

Qwen3-VL 的输入中，固定角色头部和页面图像位于本轮问题之前。以第一个 `<vision_end>` 结束位置为边界，缓存该边界之前全部 decoder 层的 K/V。每次仍单独计算其后的真实问题、assistant 生成头和所有答案 token。

前缀身份包括固定模型 revision、处理配置、BF16/后端、图片像素身份、实际 grid、精确前缀 token IDs 和 mRoPE 位置。保存的是带 DeepStack 注入后的真实语言 K/V，不是把视觉 embedding 当作语言 KV。不同图片、不同头部或位置配置必须 miss。

持久缓存只读；每条请求把公共前缀复制到独立工作 KV，再追加问题和生成状态。必须验证请求一的追加不会修改缓存，也不会影响请求二。第一轮“整段语言 KV 不跨问题复用”的原则仍成立，新的复用范围是经过明确身份检查的共同前缀。

代价也必须量出：本模型 BF16 语言 KV 每 token 112 KiB，完整视觉特征每视觉 token 16 KiB，前者是后者的 7 倍。744 个视觉 token 对应约 81.375 MiB 视觉段 KV，外加少量固定头部。它更适合正在被反复询问的活跃文档，不能预先承诺全局随机访问时也胜出。

开发阶段共享缓存上限取 1536 MiB，所有缓存方案相同；静态工作 KV、图私有池与模型参数另行测量。该数值是受控配额，实际是否在 8GB 设备内安全以峰值 allocated/reserved 和剩余显存检查为准。正式运行前在开发集选定，不能在评估集上改到有利值。

## 4. 新方向 B：减少逐 token 的主机发射开销

预分配每层静态 KV、输入 token、位置与 attention mask 所需缓冲，使用设备端累计长度更新 KV 写入位置。CUDA 图只捕获单 token 解码，图中不执行 `.item()` 或 Python EOS 分支。每步重放后仍获取真实 token 并按相同 EOS/64-token 上限停止。

图捕获后所有参与缓冲的形状和地址保持稳定；新请求通过原位复制 prefix、token 和 mRoPE delta 更新内容。图根据 GPU 游标生成本步位置与 mask，覆盖同一容量内不同页面与问题长度，避免每页重新捕获。

PyTorch 官方说明 CUDA 图的主要收益是减少 Python/C++/驱动提交开销，重放使用固定地址与执行结构：[CUDA Graph 文档](https://docs.pytorch.org/docs/stable/notes/cuda.html#cuda-graphs)。静态 KV 的接口与限制参见 [Transformers cache 文档](https://huggingface.co/docs/transformers/cache_explanation)。原型以本机已安装源码为准。

硬件证据必须来自真实 VLM decode：相同 token 步数下的 CUDA runtime 发射计数、实际 decode 时长与 GPU 内存。第一轮“decode+主机余项”不是纯 GPU 解码时间，不能直接宣称这些时间都能被图消除。

启动时单独记录图构建、预热、快照恢复时间；给出收益摊销条件。图的首次构建不能从系统成本里消失。正式单元只在共同启动规则之后测稳定推理，另设冷启动对照。

## 5. 第一阶段开发验证（已完成）

代码位于 `experiments/cross_layer_v2/`，不修改第一轮被冻结的 `src/vlmbench/`。

先对三页六个真实问题做接口检查，再对完整 282 问执行质量门槛。比较六条路径：

| 路径 | 用途 |
| --- | --- |
| NATIVE | 原生完整推理，防止新参考实现人为变慢 |
| VISUAL_HF | 原生生成器加已有视觉缓存，作为强软件基线 |
| STATIC_EAGER | 视觉缓存、静态 KV、普通逐步执行，隔离静态布局和生成循环重写的影响 |
| PREFIX | STATIC_EAGER 加公共前缀复用，检验 A |
| GRAPH | STATIC_EAGER 加 CUDA 图，检验 B |
| BOTH | A+B，检验组合 |

开发计时采用原开发划分中前 16 个至少有两问的页面，先用每页第一条不同的真实问题预热，再测其余全部真实问题。三组固定种子随机化方案执行顺序，对相同问题形成配对比较。这里是**明确标记的热页面开发诊断**，不作为全工作集、冷启动或开放环的正式结论。

另对相同八步解码采集 CPU/CUDA profiler，统计实际 runtime 调用，避免用 Tensor 加法微基准代替真实模型。

开发集质量门槛已通过，六路径各 282 问。GRAPH 与 STATIC_EAGER 的 token 282/282 一致，BOTH 与 PREFIX 282/282 一致；静态执行/前缀切分相对原生的数值差异单独记录，未降低 ANLS 门槛。

热页面 57 问、三个配对区组的实际结果：A 将 TTFT 从 113.2 降至 55.7 ms；B 将 decode 从 49.0 降至 18.5 ms/token；组合完整生成从强基线 VISUAL_HF 的 373.5 降至 158.7 ms，约 2.35 倍生成阶段速度。相同八步真实解码的 host 发射调用从 14,352 次 cudaLaunchKernel 变为 8 次 cudaGraphLaunch，模型内部的 GPU kernels 仍执行。

这些是热页面 B=1 开发验证。完整开发扫描中包含 64 次首次 miss，前缀方案 p95 存在代价；图构建总计 6.29 s，KV 状态约为视觉特征的 7 倍。上述数字和显存成本均见[开发验证报告](../experiments/cross_layer_v2/开发验证报告.md)，不能替代正式新评估结果。

GPU 不变量检查也已通过：持久前缀只读、工作 KV 独立、跨页面与问题状态隔离、图地址不变、960-token 输入和 64-token 输出的容量边界、驱逐后重新 miss。

```bash
./stage_2/experiments/cross_layer_v2/run.sh report
./stage_2/experiments/cross_layer_v2/run.sh all \
  --output stage_2/experiments/cross_layer_v2/results/replay-new
```

本轮复用现有 PyTorch、Transformers、CUDA 和模型权重，不安装或重建基础环境。精确运行参数、代码哈希、原始答案、逐请求时间和 profiler trace 均保存到结果目录。

## 6. 采用门槛与正式实验设计

采用前同时满足：

1. 全部开发问题正常生成，原始答案和 token 保留，ANLS 相对原生下降不超过 0.005。
2. 图与相同静态 eager 路径的 token 序列一致；前缀开关带来的浮点差异单独评估，不能用“同样是 BF16”代替验证。
3. 前缀实际命中时，语言 prefill token 数确实下降；GPU 图实际减少 CUDA host 发射调用，且正常 EOS decode 时间有收益。
4. 新工作 KV 与持久前缀不共享可写存储，跨问题、跨页面、不同长度和接近容量边界的测试通过。
5. 模型、缓存、工作 KV、图池和临时缓冲的总峰值在本机可用显存内，记录图创建与缓存复制成本。

门槛通过后再冻结新正式协议：

- 保留完整推理与 VISUAL_HF 强基线，使用 STATIC_EAGER/PREFIX/GRAPH/BOTH 的 2×2 消融分离软件复用和 GPU 执行收益。
- 正式测量 B=1 交互延迟，并增加原生/视觉缓存 B=2 对照；各方案的请求集合、缓存预热规则、资源配额相同。
- 以连续同页和 16 页交错为目标负载，全局随机作为局部性控制；控制问题成员集合，不先按顺序截断而改变数据。
- 每页一次、全部缓存冷启动、首次建图和不同缓存预算作为边界对照；不能只挑热命中样本。
- 主指标为真实 TTFT、完整答案延迟、decode ms/token、总吞吐和 ANLS；开放环 SLO goodput 作为服务扩展，不能替代模型阶段收益。
- 三个种子配对独立进程，按预先冻结的样本数与窗口报告均值/SD/区间，不追加种子直到出现显著结果。
- 优先从尚未用于前轮评估的原始 validation 来源文档中固定新评估集；原有结果保留作历史对照，开发选择不读取新评估输出。

如果某方向不满足门槛，保留记录并先修正语义或选择其他硬件路径，不降低质量门槛，也不把没出现的瓶颈写成优化效果。
