# AI 使用说明

本次作业使用 Codex 辅助检查实验计划、确认环境、编写测试与审阅设计文档。另有一项使用本地 Qwen3-0.6B 的缓存策略离线选参实验。

## 1. 完善实验计划并补充验证

我以 DocVQA 的同页多问为负载，计划保留完整视觉特征，按成本选择是否驻留前缀 KV，并把单 token 解码的 K、V 写回与游标更新融合到一个 GPU kernel。Codex 辅助检查这些方案在 8 GB 显存上的可行性，并补充缓存预算、回访顺序及固定 CUDA Graph 下的融合写回消融。

针对方案里的关键假设，补充了异页不应命中、同页不同问题的请求状态隔离、静态 KV 容量边界和 CUDA Graph 重放检查。实验计划还加入了逐项消融、CUDA trace、不同页面访问顺序的对照以及同一模型的 vLLM 对照。这些实验分别用于判断每项优化的作用，并检查效果是否随访问方式变化。[实验方案](../plan/推理框架对比实验方案.md) · [开发验证报告](../experiments/cross_layer_v2/开发验证报告.md)

## 2. 检查环境是否可用

Codex 辅助核查 WSL2 中的 Python、PyTorch、Transformers、CUDA 和 NVIDIA 驱动，检查现有权重能否离线加载，以及基础图文问答和 CUDA Graph 是否可运行。vLLM 对照复用了本机已有的 0.32.0 Docker 镜像。环境可用性以本地探测输出、烟测和实际推理记录为依据。[环境清单](../env/实验配置清单.md) · [vLLM 环境](../experiments/framework_compare/README.md#固定镜像和资源)

## 3. 辅助编写测试代码

Codex 辅助编写环境烟测、运行时检查、对照测量和数据复算脚本。运行时检查覆盖缓存命中、状态隔离、容量边界和解码输出一致性。测量脚本保存逐请求答案、延迟、缓存计数和 GPU 采样，复算脚本按固定口径从这些记录检验结果。AI 也辅助实现 Z3 的性质检查、故障对照和 SMT2 重放脚本。实测数值由本地推理获得，形式化查询由 Z3 求解。[本轮 GPU 状态检查](../experiments/adaptive_kv/fused.py) · [原始数据复算](../tools/check_submission.py) · [形式化验证](../experiments/cross_layer_v2/formal/README.md)

## 4. 审阅我手写的设计文档

Codex 辅助梳理我手写的文档，对照代码、实验表格和原始记录查找遗漏与表述错误。检查重点包括计时起点是否一致、加速比是否引用同一组对照、开发消融与独立评估是否区分清楚，以及形式化结论是否写明假设和适用范围。设计文档第 4 章记录了实验方法和结果，第 5 章说明适用范围。[设计文档](设计文档.md)

## 5. 缓存优化中的 AI

设计文档第 2.3 节将离线选参纳入成本缓存优化。第 3.3 节说明参数如何进入运行时，第 4.3 节给出实测结果。Qwen3-0.6B 在 CPU 上读取开发集三组缓存策略的延迟、命中和输出一致性，选出的配置冻结后在独立集重新测量。

模型选择了默认成本配置，与固定默认策略持平。与开发集直接排序选出的宽配额相比，AI 所选配置在交错回访的平均首 token 延迟为 189.6 ms，宽配额为 219.4 ms。按页连续时两者分别为 188.9 ms 和 183.1 ms。两种访问顺序等权后，AI 所选配置的平均首 token 延迟低 6.0%。

选参采用 CPU BF16、2 个线程、关闭 thinking，在三个单 token 候选中比较 logits。本次模型前向为 12.96 秒，含加载为 14.44 秒。 [实验与复现](../experiments/adaptive_kv/README.md) · [权重锁](../experiments/ai_cache_tuning/policy-model.lock.json) · [提示词和决策记录](../experiments/adaptive_kv/results/main/decision.json)
